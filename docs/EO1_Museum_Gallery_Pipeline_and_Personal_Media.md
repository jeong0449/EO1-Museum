# EO1-Museum: 갤러리 파일 생성 구조와 개인 미디어 통합 설계

작성일: 2026-11-09  
상태: **현행 The Met 파이프라인 정리 + 개인 갤러리 확장 설계안** (구현 완료 문서 아님)

## 1. 목적과 기본 원칙

EO1-Museum에서 The Met 소장품, Met Highlights 아카이브, Wikimedia Commons 자료, 개인 사진·동영상을 전시할 때의 파일 생성 관계와 확장 과제를 정리한다.

- **`original/`은 현재 전시할 원본 파일을 담는 공통 입력 디렉터리**로 사용한다. 개인 갤러리 전용 관리 시스템이나 별도 영구 컬렉션 구조를 필수로 만들지 않는다.
- 이용자가 전시할 작품 약 100개를 선택해 `original/`에 넣은 뒤 `make_gallery.py`를 실행하는 작업 흐름을 기본으로 한다.
- 원본 파일은 변경·삭제하지 않고, 화면용 결과물만 별도로 생성한다.
- 자료 수집과 아카이빙은 출처별 도구가 담당하고, 전시용 변환과 목록 생성은 `make_gallery.py`가 담당한다.
- 기존 The Met 전시와 EO1 Safe Sync의 동작을 유지하는 것을 우선한다.

## 2. 현행 The Met 파이프라인: 파일별 생성 주체

| 파일 | 생성 주체 | 역할 | 구분 |
|---|---|---|---|
| `MetObjects.csv` | The Met 공개 데이터; 로컬 다운로드 | 작품 검색용 원천 데이터 | 수집 입력 |
| `original/`의 이미지 | `GET_MET_ART_KEYWORD.py` | 다운로드한 원본 이미지 | 전시 입력 |
| `met_metadata.json` | `GET_MET_ART_KEYWORD.py` | 다운로드한 The Met 작품의 원천 메타데이터 | 전시 입력(선택적 확장 고려) |
| `metadata/*_downloaded.json` | The Met 다운로드 파이프라인 | 다운로드 관련 보조 정보 | 전시 필수 여부 미확인 |
| `display/` | `make_gallery.py` | 화면용 이미지 등 가공 결과물 | 전시 출력 |
| `images.js` | `make_gallery.py` | 갤러리 재생 목록을 담는 JavaScript 파일 | 전시 출력 |
| `artwork_info.json` | `make_gallery.py` | 현재 전시 작품의 설명 정보 | 전시 출력 |

**주의:** `images.js`는 JSON 파일이 아니라 JavaScript 파일이다. 최신 `index.html`, `server.py`, `make_gallery.py`, Android 코드에서 파일별 필수 여부와 실제 소비 경로는 아직 재확인해야 한다.

## 3. 현행 The Met 데이터 흐름

```text
MetObjects.csv
     │
     ▼
GET_MET_ART_KEYWORD.py
     ├── original/               원본 이미지
     ├── met_metadata.json       작품 메타데이터
     └── metadata/*_downloaded.json (보조 정보)
              │
              ▼
        make_gallery.py
     ├── display/                화면용 이미지
     ├── images.js               전시 목록
     └── artwork_info.json       작품 설명
              │
              ▼
       PC Gallery (index.html)
              │
              ▼
       EO1 Android Gallery
```

`MetObjects.csv`는 작품 검색의 출발점이며, 이미지는 별도로 다운로드한다.

## 4. 자료 출처가 달라도 전시 입력은 동일하게

| 자료 출처 | 수집·보관 방식 | 전시 준비 |
|---|---|---|
| The Met 일반 소장품 | `GET_MET_ART_KEYWORD.py` | 선택한 파일을 `original/`에 둔다 |
| Met Highlights | `Met_Highlights_Manager.py`로 별도 아카이브 보관 | 전시할 작품만 `original/`로 복사한다 |
| Wikimedia Commons | 별도의 검색·다운로드 경로 | 선택한 파일을 `original/`에 두고 라이선스·저작자 정보를 가능한 한 보존한다 |
| 개인 사진·동영상 | 이용자가 직접 선택 | 원본 파일을 `original/`에 둔다; 별도 메타데이터는 요구하지 않는다 |

Met Highlights 전체 아카이브와 현재 전시용 `original/`은 목적이 다르다. 원본 아카이브를 직접 수정하거나 전시 생성 과정에서 삭제하지 않는다.

## 5. 개인 갤러리의 입력과 처리 요구사항

개인 갤러리는 휴대폰 등에서 생성된 **가로·세로 정지 이미지 및 가로·세로 동영상**으로 구성한다. 사진의 EXIF 방향, 동영상의 회전 메타데이터, 코덱, 해상도, 프레임 레이트, HDR 여부가 서로 다를 수 있다.

| 입력 | `make_gallery.py`에서 필요한 처리 | 전시 출력 |
|---|---|---|
| 세로 사진 | EXIF 방향 반영, 화면에 맞게 축소·변환 | 세로 정지 이미지 |
| 가로 사진 | EXIF 방향 반영, 전시용 정지 이미지 및 기존 패닝용 이미지 생성 | 정지 이미지 / 패닝 |
| 가로 사진의 패닝 비디오 | **필요한 전시 모드에서만** PC 측 렌더링 | EO1 호환 MP4 (선택 사항) |
| 세로 휴대폰 동영상 | 회전·코덱·HDR·해상도 확인 후 필요 시 변환 | EO1 호환 MP4 |
| 가로 휴대폰 동영상 | 회전·코덱·해상도 확인 후 필요 시 변환 | 비율을 유지한 EO1 호환 MP4 |

### 5.1 가로 사진: 세 가지 결과물의 구별

1. **전시용 정지 이미지:** 가로 사진 전체를 세로 화면에 맞춰 표시하는 버전.
2. **패닝용 이미지:** 기존 갤러리의 좌우 패닝에 사용할 이미지. 현행 생성·재생 방식을 우선 확인한다.
3. **패닝 비디오:** 그래픽 처리 부담을 줄이기 위해 좌우 이동을 MP4로 미리 렌더링한 버전. 모든 사진에 자동 생성할 필요는 없다.

**확인 필요:** 현재 파이프라인에서 패닝 비디오가 이미 생성되는지, 생성된다면 어느 스크립트가 담당하는지 최신 소스로 확인한다. 기존 기능을 중복 구현하지 않는다.

### 5.2 휴대폰 동영상: EO1 호환성

EO1은 Android 4.4.2 기반이므로, MP4라는 확장자만으로 재생 가능성을 보장할 수 없다. PC에서 FFmpeg 등을 이용해 다음과 같은 **초기 호환성 목표**로 변환하는 방안을 검토한다.

| 항목 | 제안 설정 |
|---|---|
| 컨테이너 | MP4 |
| 영상 코덱 | H.264/AVC |
| 프로파일 | Baseline 또는 Main (실기기 확인) |
| 픽셀 형식 | `yuv420p` |
| 프레임 레이트 | 최대 30 fps |
| 화면 크기 | 1080×1920 화면 범위 내에서 원본 비율 유지 |
| 오디오 | AAC 또는 무음; 음성·음악 처리 정책은 별도 결정 |
| 재생 시작 최적화 | `+faststart` |

HEVC/H.265, HDR, 고해상도·고프레임레이트, 회전 메타데이터 등을 고려한다. 위 설정은 **검증 전 권장안**이지 EO1에서 모두 정상 작동한다고 확인된 사양은 아니다. 필요 시 해상도·비트레이트를 더 낮춘다.

동영상은 일반 이미지 전환 타이머와 분리하여 **영상 종료 시 다음 작품으로 진행**하는 것이 목표다. 재생 실패·중단·너무 긴 영상의 처리 정책도 확인한다.

## 6. 메타데이터가 없는 파일의 처리

개인 사진·동영상은 `met_metadata.json`에 항목이 없어도 정상 처리해야 한다.

- 메타데이터가 있으면 기존 작품 설명을 활용한다.
- 없으면 제목을 파일명에서 유도하거나 설명을 비운다.
- `artwork_info.json`은 메타데이터 유무와 관계없이 갤러리에서 읽을 수 있는 **기존 형식**으로 생성한다.
- 설명이 없는 사진에서 설명 패널은 비우거나 숨기도록 처리한다.
- EXIF 촬영 시각은 추후 선택적으로 사용하고, GPS 위치 등 사생활 정보는 기본 표시하지 않는다.
- Wikimedia Commons 작품은 메타데이터가 선택적이더라도 저작자·출처·라이선스 표시 의무를 별도로 고려한다.

**구현 전 확인:** 실제 `artwork_info.json`의 키 구조와 파일명 매칭 규칙을 최신 코드에서 확인한다. 새로운 임의 스키마를 도입하지 않는다.

## 7. 확장 후 목표 파이프라인

```text
The Met ──────────────┐
Met Highlights ───────┤
Wikimedia Commons ────┤──► 전시할 파일 선택 ──► original/
개인 사진·동영상 ──────┘                           │
                                                ▼
                                         make_gallery.py
                                                │
                             ┌──────────────────┴──────────────────┐
                             ▼                                     ▼
                        정지 이미지 처리                       동영상 처리
                     방향 보정·크기 조절                     형식 확인·변환
                     가로 이미지 패닝 처리                  EO1 호환 MP4 생성
                             │                                     │
                             └──────────────────┬──────────────────┘
                                                ▼
                                    display/ 등 전시 출력물
                                    images.js
                                    artwork_info.json
                                                │
                                                ▼
                                         PC Gallery
                                                │
                                                ▼
                                        EO1 / Safe Sync
```

이 그림은 **목표 설계**이다. 실제 영상 파일의 출력 경로, `images.js`의 미디어 항목 형식, EO1 전송·재생 경로는 최신 소스 확인 후 결정한다.

## 8. 개발 순서와 검증 항목

### 1단계 — 현행 코드 대조

- `make_gallery.py`가 읽는 확장자, 원본 탐색 방식, `display/` 재생성·삭제 동작 확인.
- `images.js` 및 `artwork_info.json`의 실제 출력 스키마와 `index.html` 소비 방식 확인.
- 가로 이미지 패닝과 기존 MP4 재생이 PC/EO1에서 각각 어떻게 구현되는지 확인.
- `server.py` 및 `MainActivity.java`에서 미디어 목록, Safe Sync, 영상 재생 지원 범위 확인.

### 2단계 — 메타데이터 없는 정지 이미지

- 개인 JPG/PNG 등으로 `make_gallery.py` 실행.
- 가로·세로 이미지의 방향·크기·패닝 결과 확인.
- 설명 정보가 없는 작품에서도 갤러리 재생이 중단되지 않는지 확인.
- The Met 작품으로 회귀 테스트.

### 3단계 — 개인 동영상

- MP4/MOV 입력 인식과 FFmpeg 설치·오류 처리.
- 회전, 화면 비율, 코덱 변환 및 결과 파일명 충돌 방지.
- PC Gallery와 EO1에서 영상 재생, 종료 후 다음 작품 전환 검증.
- Safe Sync 시 저장 용량·전송 시간·중단 복구 확인.

### 4단계 — 선택적 고도화

- 가로 사진 패닝 비디오를 필요할 때만 생성.
- 변환 완료 파일 재사용(입력 변경 시에만 재생성) 검토.
- Wikimedia Commons의 라이선스·저작자 표시와 개인 사진 EXIF 활용 정책 검토.

## 9. 현재 결정한 사항과 아직 미정인 사항

**결정한 사항**

- 개인 갤러리 전용 관리 시스템은 만들지 않는다.
- 현재 전시할 파일은 모두 `original/`에 모은다.
- `make_gallery.py`가 전시용 파일 생성의 중심 역할을 맡는다.
- 메타데이터 없는 개인 사진도 지원한다.
- 휴대폰 동영상은 EO1 호환 형식으로 처리해야 한다.
- 기존 The Met 전시 기능을 유지한다.

**최신 코드 검토 후 결정할 사항**

- 영상 출력 파일의 위치와 재생 목록 형식.
- 가로 사진 패닝 비디오 생성 주체 및 활성화 조건.
- PC Gallery와 EO1에서 영상 종료 이벤트를 처리하는 방식.
- 기존 `art/` MP4와 개인 동영상의 관계.
- `metadata/*_downloaded.json` 및 기타 파일의 실제 필수 여부.
